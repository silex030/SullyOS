# SullyOS ethernet 自改版

> 这是 SullyOS 的个人自改版（ethernet 分支），不是原版官方发布。
> 写给不写代码的使用者：只讲现在有什么功能、从哪里打开、需要你准备什么。
> 版本 `v3.23 (Travel & Voice)`，本文更新于 2026-11-02，主分支 HEAD `5719b238`。
> 文档完成不代表已部署：本轮只做到本地接入与必要测试通过，没有重新部署，也没有生成安装包。

## 先认识一下这个版本

**SullyOS** 是一个装在浏览器里的虚拟手机系统：有桌面、有 App、有消息通知、有相册。你可以创建角色，把他们放进系统，像真的用手机一样跟他们互动。默认内置了一个角色 **Sully**（一只话痨黑客猫），你也可以删掉它，换上自己的人。

**ethernet 自改版和原版的关系**：

- 原版（上游）：`qegj567-cloud/SullyOS`，本版从它分叉出来，之后一直在自己的 `ethernet` 分支上改。
- 大方向只有两句：**能自己托管的服务就搬回自己手里**，**拟真生活玩法尽量做大**。
- 下面功能清单里标了 **[自改]** 的是这个版本自己加的或大改的，没标的就是从上游继承、一直保留的。

## 开始之前：三件必须知道的事

1. **角色说话要联网调模型**。数据平时存在你的浏览器本地，但每次让角色回话、解读、总结，都会把组装好的提示词发给你自己填的模型服务。这不是离线软件。
2. **你需要自己准备一个大模型 API**（见后面「让角色开口说话」）。不填也能点开各个 App 看，但角色不会回话。
3. **换浏览器、清缓存会丢数据**。务必定期去「设置 → 导出」打备份包存好。

## 本轮（2026-11-01）同步/接入的重点

以主分支实际代码和验收结论为准，重点是这几项：

1. **哔哔**：桌面新 App，纯本地动态，发帖配图、评论点赞、未读删除，不调模型。导入后重新解析已有图片引用；JSON 模块包不含图片二进制，换设备或图片库已清除时不能单包恢复图片；系统整包图片链本轮未验证。
2. **三处阅读样式分享落到各自视图**：见面设置「阅读样式分享」只影响本角色见面记录、剧情放映厅外观「阅读样式分享」只影响故事正文、协作窗口设置「正文样式分享」只影响这个协作窗口，目标类型包不能混用；取消不保存，有覆盖时用面板上「恢复原样式」去掉这层。
3. **PDF 与设置恢复更稳**：PDF 文字提取有页数上限、失败自动清理；设置损坏时保留旧值、不写入坏数据。
4. **链接分享卡与按需摘录**（既有 ethernet 历史同步的改进，不是哔哔新功能）：聊天里发的 B站 / 小红书 / 普通网页链接会生成内容卡，角色在回话时可以按需读正文和评论（只读本轮出现过的卡，有用量上限，读不到就按简介回，不硬编）。本项不拿 PDF 的测试当专项验收。
5. **3D 房间**：在「小小窝」房间内右上「🧊 3D房间」进入：摆桌椅床灯书架圆毯，选中移动/旋转；布局按角色隔离存 localStorage、重开自动恢复，并经薄备份适配纳入系统备份（已测范围仅模块保存/读取→备份适配器恢复 + OSContext 真实接线；系统整包 ZIP 本轮未专项复验）。
6. **万圣节寻物（2026-10-29–31）**：在「特别时光」里，按手机实际日期显示未开始/进行/已结束；收集 6 处糖果点位、一次领取；奖励是本地纪念糖果收集记录（领取凭证），不计入银行/捕鱼余额；领取状态存 localStorage 并纳入系统备份（已测范围同上，未做全系统 ZIP 端到端）。
7. **错误提示脱敏**：含凭据/认证信号的错误整段隐藏（「详情已隐藏」），兄弟 code/type 保留；裸随机串等启发式边界见代码注释。已接入。

## 你的数据存在哪

- **存在你浏览器本地的**：聊天记录、角色设定、世界书、图片（二进制单独存，省空间）、下载的书、记的账。技术上叫 IndexedDB，你不用记这个名字。
- **会离开设备的**：凡是让角色说话、总结、解读、生图、查热榜、同步记忆向量的动作，都会按你填的地址去调对应的服务。聊天记录本身不会被上传到任何公共库，但提示词要发给模型服务才能生成回复——这是所有这类应用的共同做法。
- **备份在你自己手里**：导出包、WebDAV、GitHub 备份全是你自己的账号和地址，备份包默认不上传到公共库。备份包里仍含聊天、角色等内容，密钥默认脱敏但不等于无隐私，分享前请自行检查；后端连接为用户可选保留项。
- **可选的云端件**：记忆向量同步（你自己的 Supabase）、透视窗记录（你自己的 Supabase）、主动消息后端（你自己的 VPS 服务或站长提供的地址，启用时相应服务状态/数据库可在自有服务器）。不填就纯本地用，只是对应功能不开。

## 让角色开口说话

打开「设置」，填三行：

| 字段 | 填什么 |
|------|--------|
| Base URL | 模型服务的地址，如 `https://api.openai.com/v1`。注意结尾不要带 `/chat/completions`，带了程序会自动去掉 |
| API Key | 你的密钥，别告诉别人 |
| Model | 模型名，如 `gpt-4o-mini`。设置里可以直接拉一次模型列表，不用手打 |

语音（可选）：MiniMax、Fish Audio、ElevenLabs 三选一，在「设置 → 其他 API」填对应服务的 Key，再到角色页填音色 ID。不填也能正常文字聊天。

## 常见问题

**角色不回话？** 先看 API Key 填了没、模型名对不对。Base URL 结尾误带 `/chat/completions` 的会自动纠正，存量坏值下次打开自动好。

**语音没声音？** 看语音 Key 和音色 ID 填了没，或者浏览器有没有禁音频权限。

**能部署到服务器吗？** 能。`pnpm build` 出来的 `dist` 丢到任何静态托管就行。后端地址按所选部署方式配服务地址/反代，仓库里不写死任何后端域名，发布前记得在部署面板填好。
